# VPN для gamelife.shop

MVP управления доступом к Hiddify Manager. Оператор через закрытый HTTP API задаёт срок действия и общий лимит трафика, получает страницу подключения клиента и может отозвать доступ. PostgreSQL хранит условия подписки и очередь изменений. Изменения отправляются в Hiddify API v2. Расчёты с клиентами на этом этапе ведёт оператор.

## Размещение на общем VPS

Проект использует два независимых стека Compose. `gamelife-hiddify` содержит панель, её MariaDB и Redis. `gamelife-vpn` содержит Go API и PostgreSQL. Каждый стек получает собственные тома. На хосте по умолчанию доступны `127.0.0.1:28443` для панели и `127.0.0.1:18090` для API. Публичный TLS и маршрутизация домена остаются у существующего Caddy. Панель работает в собственной сетевой среде с NET_ADMIN. Публичные профили в этой схеме должны использовать транспорт, который проходит через HTTP reverse proxy, например VLESS через WebSocket и TLS. Для контейнеров настроены ограничения памяти и CPU, а Go-приложение собирается на GitHub Actions.

Закреплённый образ Hiddify уже содержит пакет панели. Стартовый сценарий использует этот пакет без повторной установки и не меняет рекурсивно права исходников; права каталога данных по-прежнему настраивает Hiddify. Сценарий проверяет ожидаемые строки оригинального образа. При обновлении digest нужно повторно проверить совместимость и CI.

### Первый запуск

1. На VPS понадобятся Linux, Docker Engine с Compose v2.20 или новее, Bash, OpenSSL, curl и flock. Проверьте свободное место, оперативную память и занятость двух локальных портов командой `ss -lnt`. Номера портов настраиваются переменными из [.env.example](.env.example).
2. Для автоматической доставки добавьте в GitHub **Settings → Secrets and variables → Actions** секреты `DEPLOY_HOST`, `DEPLOY_USER` и `DEPLOY_SSH_PRIVATE_KEY`. Workflow использует SSH на порту 22 и сверяет ED25519-отпечаток с ранее сохранённым для VPS домена. При замене сервера сверьте новый отпечаток с консолью хостинга и обновите ожидаемое значение. Пользователю деплоя нужен доступ к Docker и запись в собственный домашний каталог.
3. В **Actions → Deploy → Run workflow** на `main` выберите `inspect` и проверьте доступ к Docker, свободные локальные порты и ресурсы сервера. После успешного **Verify** выберите `deploy`. Первая доставка создаёт `~/services/gamelife-vpn/.env` с правами 0600 и случайными паролями, запускает панель и ждёт её TLS-вход. Последующие успешные проверки коммитов `main` запускают доставку автоматически. Перед запуском проверяется, что проверенный коммит всё ещё находится на вершине `main`. Версии кода лежат в `releases/<commit>`, текущая в `current`. Команды SSH записывают в журнал только краткий разрешённый список результатов.
4. На сервере из каталога `current` выполните `docker compose --env-file ../../.env -f compose.panel.yaml exec panel hiddify admin` **из физического каталога релиза** (`cd -P ~/services/gamelife-vpn/current`). Административная ссылка содержит секрет. Для первого входа подключитесь через доверенный канал к локальному порту 28443 с путём из ссылки. Для проверки подлинности начального сертификата возьмите его отпечаток через уже доверенное SSH-соединение.
5. В панели добавьте `gamelife.shop` в режиме CDN и настройте профили с транспортом WebSocket/TLS для работы через HTTP reverse proxy. В профилях указывается публичный порт 443. Примените настройки панели. Caddy завершает публичный TLS; соединение от Caddy до панели идёт по внутренней Docker-сети.
6. Укажите имя существующей Docker-сети Caddy в `CADDY_NETWORK` серверного `.env` и повторите Deploy: панель подключится к ней под именем `gamelife-vpn-origin`. В конфигурации Caddy замените блок **только для gamelife.shop** по образцу [deploy/Caddyfile.example](deploy/Caddyfile.example). Не записывайте адреса и заголовки запросов панели в журналы: ссылки на профили содержат секреты. Сохраните прежнюю конфигурацию, проверьте полную новую конфигурацию командой `caddy validate`, затем выполните штатный reload из управляющего Caddy проекта.
7. Создайте в Hiddify отдельного администратора с правом управления своими пользователями. В серверном `~/services/gamelife-vpn/.env` заполните `HIDDIFY_API_KEY` его UUID, `HIDDIFY_ADMIN_BASE=https://gamelife.shop/<admin-path>` и `HIDDIFY_CLIENT_BASE=https://gamelife.shop/<client-path>`. Базовые адреса содержат пути из настроек панели, без UUID и суффикса API. Повторный **Deploy** поднимет PostgreSQL и Go API. `curl -fsS http://127.0.0.1:18090/healthz` возвращает HTTP 204, когда API видит свою БД.

Оба стека также можно поднять напрямую из checkout с заполненным `.env`:

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o vpn-api .
docker compose -f compose.panel.yaml up -d --wait --wait-timeout 600
docker compose up -d --build --wait
```

### Управление доступом

Выполняйте запросы на сервере или по SSH-туннелю. Загрузите `VPN_ADMIN_TOKEN` из серверного `.env` в окружение текущего оператора. Идентификатор клиента — внутренний ID заказа или клиента, до 64 букв ASCII, цифр, дефисов или подчёркиваний.

```sh
api=http://127.0.0.1:18090/v1/subscriptions
until_date=$(date -u -d '+30 days' +%F)
curl --fail-with-body -X PUT "$api/customer-001" \
  -H "Authorization: Bearer $VPN_ADMIN_TOKEN" -H 'Content-Type: application/json' \
  --data "{\"valid_through\":\"$until_date\",\"quota_gb\":50}"
curl --fail-with-body "$api/customer-001" -H "Authorization: Bearer $VPN_ADMIN_TOKEN"
curl --fail-with-body -X DELETE "$api/customer-001" -H "Authorization: Bearer $VPN_ADMIN_TOKEN"
```

`valid_through` включает указанную дату по UTC. `quota_gb` — суммарный лимит профиля с момента его создания. Для продления укажите новую конечную дату и новый общий лимит. Счётчик потреблённого трафика сохраняется. Повтор одного PUT сохраняет тот же профиль и условия. DELETE отключает профиль, а повторный PUT позволяет его включить.

HTTP 202 и `sync=pending` означают, что изменение записано в PostgreSQL. После `sync=applied` GET возвращает у включённой подписки персональный `profile_url`. Его можно передать клиенту для импорта через страницу Hiddify. При отзыве доступа дождитесь `sync=applied` и `enabled=false`. Во время сбоя панели уже выданный профиль может работать до применения отзыва или до собственного лимита Hiddify. При восстановлении worker автоматически повторяет запросы с тем же UUID.

Перед первой продажей проверьте временную подписку с внешнего устройства: выдачу страницы, импорт в клиент, прохождение трафика, затем отзыв и отказ нового подключения. Проверка TLS контейнера подтверждает только готовность входа панели.

### Проверка и восстановление

Команда `go test ./...` запускает интеграционный сценарий при заданном `TEST_DATABASE_URL`. Он использует временную таблицу PostgreSQL и TLS-имитатор Hiddify. Проверяются авторизация, создание, повтор после потерянного ответа, продление, отзыв и окончание срока. CI дополнительно поднимает контейнеры на Linux и проверяет историю репозитория сканером Gitleaks с сокрытием найденных значений в выводе.

Для резервной копии сохраните дамп PostgreSQL, резервную копию штатными средствами Hiddify и защищённую копию серверного `.env`. Для отката маршрута восстановите сохранённый блок домена в Caddy и проверьте конфигурацию перед reload. Для отката версии приложения из предыдущего каталога `releases/<commit>` выполните `bash deploy/release.sh`. Тома сохраняются при обычном обновлении.
