# Подключение баз через Compose: проект интеграции

`compose.ru-assets.yaml` добавляет только read-only bind публичных баз и
подключение панели к существующей внешней сети gateway с alias
`gamelife-vpn-origin`. Сам файл не включает изменение автоматически.
`VPN_RU_ASSET_ROOT` должен указывать на стабильный каталог с `current`, а
`CADDY_NETWORK` — на уже существующую сеть. Отсутствующий source не создаётся
автоматически (`create_host_path: false`). Монтируется родитель `current`, а не
сам симлинк: тогда переключение ревизий становится видно контейнеру.

## Что необходимо до production

1. В коде основного сервера `deploy/release.sh` предусматривает opt-in через
   `/root/services/gamelife-vpn/ru-assets/compose-enabled`: обычный root-owned
   файл с правами `0600` и содержимым `v1` с завершающим переводом строки.
   Только при наличии безопасного marker и проверенных файлов подключаются оба
   файла Compose. Отсутствие marker оставляет обычный Compose, но если mount
   уже виден у панели, выпуск прекращается, чтобы не снять его незаметно.
   Код следует сначала доставить и проверить; marker сам по себе не создан.
   Штатные переменные панели, включая `VPN_HIDDIFY_PATCH_DIR` и его hash,
   сохраняются. Проверка overlay не является проверкой работы VPN.
2. CI для дочерних узлов сейчас обслуживает только subscription relay. Для
   панели нужен отдельный проверяемый release hook, который получает overlay из
   той же проверенной ревизии, использует оба файла Compose и сохраняет сеть,
   окружение, порты, базы и gateway. Нельзя обновлять узлы параллельно без
   отдельной проверки работоспособности и отката каждого.
3. Первая доставка кода на узлы должна быть двухфазной: старый dispatcher не
   выгружает новый overlay. Сначала требуется выпустить dispatcher, умеющий
   выгружать новые файлы, затем — отдельным подтверждённым CI запуском доставить
   файлы и выполнять проверки. Не считать фазу обновления relay обновлением
   панели Hiddify.
4. Операционные команды и будущие обновления также должны указывать оба `-f`.
   Вызов старого Compose без overlay может удалить mount при recreate. Само
   наличие overlay в репозитории или на VPS этого не предотвращает.
5. Перед удалением overlay необходимо вернуть шаблоны, которые ссылаются на
   mount, применить их и проверить VPN. Иначе Xray может не запуститься без
   файлов. Нужны проверка aliases, read-only mount, panel health и реальное
   подключение к каждому узлу из независимой точки до и после операции.

`test_compose_integration.py` с `RU_ASSETS_DOCKER_TESTS=1` создаёт отдельный
временный проект и внешнюю сеть, проверяет merge, alias и read-only mount до и
после `--force-recreate`, затем удаляет только свои тестовые ресурсы. Тест не
подтверждает работу реальной панели и не устанавливает overlay на узлы.
