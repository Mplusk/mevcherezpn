# Проверка маршрутизации через VPN-узлы

`live_probe.py` рассчитан на отдельную точку мониторинга с Xray и выделенным
мониторинговым аккаунтом (`/etc/gamelife-vpn-monitor/credentials.json`). Он
проверяет ответ контрольных сайтов напрямую с этой точки, затем последовательно
поднимает локальный SOCKS-туннель через каждый из трёх узлов и проверяет внешний
IP, доступность контрольного заблокированного домена и ответ обычного российского
домена. Личные подписки и профили клиентов не используются; профиль мониторинга
передаётся Xray через stdin, не записывается во временный файл и не выводится.

Вывод содержит только статусы, без URL и учётных данных. Код выхода `0` означает,
что контрольный заблокированный сайт ответил через все три узла, обычный RU-сайт
не ответил через VPN, внешний IP каждого узла совпал с ожидаемым, и оба сайта
ответили напрямую с точки мониторинга. При любом другом результате код `1`.
`connection_failed` и `http_error` различаются; отсутствие соединения само по
себе **не доказывает** серверную блокировку, поскольку может возникнуть из-за
сети, DNS или сайта. Для установления причины сравнивайте прямую доступность с
конкретного выходного VPS и порядок его правил. Профили берутся только из
root-owned файла с закрытыми правами; ссылка на подписку не выводится.

Проверка не имитирует Android-приложение, не подтверждает прямой путь из России,
не гарантирует все сайты и не проверяет приватные сети или BitTorrent. Эти
свойства требуют отдельных изолированных тестов и проверки на устройстве.

Запуск на настроенной точке от root:

```sh
python3 deploy/routing/live_probe.py
```
